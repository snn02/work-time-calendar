# Google Calendar через коннектор

Используй нативные инструменты Google Calendar, доступные в текущей среде. Названия и схемы различаются: сначала прочитай описание реально обнаруженного инструмента. Нужны список событий целевого календаря, чтение события и создание; изменение — для явного исправления. Собственный сервер, gws и личный OAuth-клиент не являются зависимостями навыка.

1. Проверь целевой calendar ID из SKILL.md и чтение указанного периода. Если список календарей недоступен, прямое успешное чтение по ID достаточно. Не меняй ACL, подписки или публичность календаря.
2. Получи все страницы, обработай повторения и границы периода. При сбое чтения не создавай вслепую — сверка не выполнена.
3. Подготовь факты: `start`, `end` с UTC offset, `project`, `category`, `action`, `description`, `basis` (`user`, `chat_estimate`, `confirmed_estimate`), `sources` (стабильные `agent:session-id`; по возможности добавь ссылки на сообщения). Для объединённого факта сохрани источники без приватных путей.
4. Сопоставь ранее записанное. Ручная запись может быть тем же фактом без служебных полей. Смысловую неоднозначность разрешает агент по данным/уточнению; не пытайся заменить её совпадением слов или времени. Сохраняй отдельные параллельные проекты.
5. Создай только отсутствующие интервалы. Не добавляй гостей, Meet, уведомления, повторы и переносы без запроса владельца. В Google Calendar app явно передавай `add_google_meet=false`, `self_attendance=omit`, пустой список attendees и reminders с use_default=false: пропущенные параметры могут включить сервисные defaults.
6. Прочитай каждое созданное событие и проверь календарь, начало/конец, заголовок, описание и идентичность. Используй URL из ответа сервиса, если он возвращён.

## Идентичность между локальным и облачным запуском

Видимые данные ограничены форматом из SKILL.md: заголовок и четыре строки описания. Служебный блок `[work-time-calendar]`, JSON, basis, ключ и идентификаторы сессий в новые описания не добавляются.

Если API/коннектор поддерживает скрытые свойства, храни идентичность там. Локальный запуск может вести приватный журнал связей event ID → исходный факт и сообщения вне навыка/общего harness. Не обещай доступ облачному запуску к локальному журналу. При отсутствии скрытых полей сопоставляй время, проект, источник, вид активности и смысл описания. Совпадение одного проекта или заголовка не доказывает тождество двух работ.

Старые служебные блоки читаются только для миграции и распознавания ранее записанного. При явно запрошенном переоформлении удали их из видимого описания, предварительно сохранив необходимые связи в доступном приватном журнале. Ручные описания и несвязанные события не заменяй автоматической сводкой.

При доступном Python помощник `prepare` формирует читаемые события и скрытую идентичность; `reconcile` вычитает покрытые части; `verify` проверяет чтение. Укажи явно пути к приватным рабочим JSON. Не сохраняй истории в папке навыка.

```text
python scripts/work_time.py prepare --entries entries.json --output prepared.json
python scripts/work_time.py reconcile --entries entries.json --events calendar-events.json --output plan.json
```

В `reconcile` неотмеченные пересекающиеся события возвращаются в `review`: для того же факта передай `calendar_matches: [eventId]`, для доказанно независимого — `distinct_event_ids: [eventId]`, затем пересчитай. Не добавляй эти решения догадкой.

Если Python отсутствует, выполни смысловое сопоставление коннектором по читаемым полям и интервалу. Не выдумывай хеши или скрытые возможности инструмента; поддержка custom event ID и скрытых полей коннектором не гарантирована. Разные описания в одном проекте с пересечением времени требуют разбора, а не автоматического слияния.

## Сбой или параллельные запуски

После тайм-аута создания результат неизвестен: сначала повторно прочитай/найди событие по ключу, источнику и интервалу. Не повторяй create сразу. Если коннектор принимает custom event ID, используй детерминированный ID помощника. Если не принимает — повтори сверку непосредственно перед create, не запускай два массовых импорта одновременно и сообщи о возможном конкурентном конфликте. Одна проверка до create не обеспечивает атомарности; не обещай абсолютную защиту без поддержки сервиса.

При ошибке прав/подключения сохрани подготовленные факты локально или в разрешённом файле текущей облачной сессии, сообщи конкретную невыполненную операцию. Не проси Google Cloud/OAuth JSON, пока пользователь не выбрал собственный API-транспорт вместо доступного приложения.

## Формат реального коннектора

Google Calendar app обрабатывает описание как Markdown: разделяй четыре поля пустой строкой (`\n\n`), чтобы сохранить их отдельными абзацами. Одиночные `\n` внутри абзаца при чтении сворачиваются в пробелы, а переданные HTML-теги экранируются и отображаются буквально. В Python используй `time_core.connector_description(event)`. При прямом API, сохраняющем plain text, оставляй обычные переносы. Проверяй представление обратным чтением.

Google Calendar app возвращает время в плоских полях start/end и сохраняет целые секунды. Нормализуй границы до секунд перед формированием ключа, иначе следующий сбор ошибочно найдёт отсутствующий фрагмент менее секунды. Ответ create может содержать HTML и entities в description, а read — обычный текст с переносами строк. Сравнивай неизменность текста и полей с нормализованными пробелами, а не буквальное HTML-оформление. Потерю слов или изменение значений по-прежнему считай ошибкой readback.
