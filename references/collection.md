# Общий сбор и текущий чат

На начало запуска зафиксируй границу чтения. «Сегодня» — от полуночи в часовом поясе профиля (по умолчанию Europe/Moscow) до момента вызова; другой день — до следующей полуночи. Ищи сообщения в периоде, включая возобновлённые старые и архивированные сессии. Локальный CLI по умолчанию использует Europe/Moscow: для другого пояса передай явные `--from`/`--to` с UTC offset.

## Сначала определи покрытие

Для общего сбора проверь четыре источника: локальные Codex, Claude Code, OpenCode и облачный ChatGPT. Для ChatGPT отдельно учти активные чаты (включая проекты) и архив. Исключай источник только по явному ограничению пользователя либо сообщай о его недоступности. В Codex desktop обнаруживай `list_threads`, `read_thread`, `list_archived_threads`, `list_projects` и следуй [chatgpt-history.md](chatgpt-history.md). Возможности локального агента не ограничиваются его файловой системой.

Перед сверкой календаря составь короткий итог покрытия: источник, статус, просмотренные страницы/чаты, есть ли продолжение, ошибки/отсутствующие метки. Статусы: прочитано, частично, недоступно, не проверено, исключён запросом. «Нет подходящих сообщений» допустимо только после успешного чтения соответствующего источника за период. При неполноте обработай обоснованную доступную часть и явно перечисли пробелы; не объявляй весь сбор полным.

При итоговом подсчёте отдельно показывай сумму по проектам и личное время как объединение пересекающихся интервалов, согласно [reporting.md](reporting.md). Две независимые работы по часу в один и тот же период дают два события, два проектных часа и один час личного времени.

## Локальные Codex / Claude Code / OpenCode

Локальная часть общего сбора из любого проекта включает все три хранилища. Помощник читает Codex `$CODEX_HOME/sessions` и `archived_sessions`, Claude `$CLAUDE_CONFIG_DIR/projects`, OpenCode `$OPENCODE_DATA_DIR/opencode.db`; по умолчанию соответствующие папки пользователя. Чтение SQLite — read-only, с согласованным WAL-снимком. Исходные журналы не меняются. Облачный ChatGPT читается отдельным этапом инструментами хоста, а не этим Python-процессом.

```text
python scripts/work_time.py collect --date today --output <личный-временный-каталог>/histories.json
python scripts/work_time.py collect --date 2026-11-01 --summary
python scripts/work_time.py collect --from 2026-11-01T00:00:00+03:00 --to 2026-11-01T18:00:00+03:00 --session codex:UUID
```

Команды запускай относительно папки навыка либо абсолютным путём. Истории и подготовленные факты не помещай в общий harness, глобальный навык, ZIP или приватный плагин. Не загружай их в Drive/другой сервис без отдельного указания владельца.

Сначала изучи `scope`, `coverage`, `pending_sources`, `errors`, перечень проектов и временные границы; затем только нужные сообщения. `scope=local_histories` и `complete=true` означают полноту только выбранных локальных хранилищ. `pending_sources` отмечает ChatGPT как `not_collected` с транспортом `host_tools`; даже `--summary` и `--source` не выполняют этот этап. В общем сборе проверь облако доступными инструментами и отдельно обнови итог покрытия. При явном запросе только локальных источников отметь облако как исключённое запросом. Старый экспорт без этих полей также не доказывает чтение облака. Нет сообщений Claude за день при успешном чтении — допустимый нулевой результат; недоступная база — неполное покрытие.

Определи смысловые блоки по сообщениям человека и ответам, отмечай оценки. Не считай весь разрыв first–last непрерывной работой. Системные сообщения, сжатие контекста, команды/результаты инструментов, подагенты, автономные проверки и повторённые сообщения после resume/fork не образуют отдельную личную работу. Помощник удаляет явные дубликаты; если версии формата не дают доказать происхождение копий, проверь их по содержанию и временным меткам. Одинаковые слова сами по себе не доказывают дубликат. Не приписывай ожидание агента пользователю без основания.

Для одиночного сообщения без обоснованного конца не добавляй буфер: вынеси интервал на уточнение. Достаточно обоснованные интервалы можно записать по просьбе «запиши» как `chat_estimate`, явно сообщив, что это восстановление по истории. Не проси подтверждать каждый очевидный проект отдельно.

В режиме текущего чата находи нужный source ID и ограничивай выборку им. Если он недоступен, используй явно переданное описание и уточни время; режим самопроизвольно не расширяется на другие чаты.

## Облачные ChatGPT / Claude

Подключённый Google Calendar даёт доступ к календарю, но не к файловой системе компьютера и историям другого сервиса. Доступ к истории проверяй отдельно в любой среде: в Codex desktop облачный ChatGPT может читаться через инструменты приложения. Для других облачных сред используй реально доступный поиск собственных чатов/проектов, затем прочитай найденные оригиналы с временем. Не выдавай память или поисковые сниппеты без меток за точный интервал. Отсутствие инструментов ChatGPT не доказывает недоступность всех локальных историй, и наоборот.

Для дня из локальных трёх агентов используй предоставленный экспорт локального сборщика либо явно выбранный владельцем подключённый источник. Не требуй установки сборщика для ручных записей и календарных отчётов. Если общего источника нет, подготовь доступную часть, назови недоступные источники и предложи выполнить `collect` локально и передать экспорт. Не обещай автоматический общий сбор из недоступных чатов.

Для переноса достаточно нормализованных фактов/фрагментов с датами, source IDs, проектом, типом, временем и основанием; передача всех сырых переписок не обязательна. Переносимый формат записи описан в calendar.md.
